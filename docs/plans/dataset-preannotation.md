# RoboMark 数据集批量预标注与审核实施计划

创建日期：2026-10-11（Asia/Shanghai）  
当前阶段：功能实现与隔离环境验收完成；真实模型质量待用户服务试运行。

## Goal

为 RoboMark 实现通用的数据集批量预标注与人工审核功能：用户自行配置 vLLM 或其他 HTTP 推理服务的 endpoint、认证、请求格式和响应映射，在数据集上输入 Prompt（例如“标注所有无人机”），由独立后台 worker 执行持久化任务；模型结果经过结构与业务验证，转换为当前矩形框或四点标注 Schema，作为可编辑候选框叠加在图片上。用户可筛选结果、修改或删除框、补画、保存草稿及审核，通过后安全合并为正式标注。关闭页面、服务重启、重试和重复审核均不丢失已保存结果，不覆盖人工标注，不重复导入。

## 1. 范围与产品流程

### 1.1 数据集操作

1. 在数据集页面提供“预标注”和“浏览 / 审核图片”入口。
2. 用户选择推理配置，输入 Prompt，指定目标类别或类别映射及标注形状。
3. 支持抽样试运行；抽样和全量执行使用同一请求、转换、验证与后台执行管线。
4. 全量任务覆盖创建时该数据集的全部图片，固定图片清单；之后导入的新图片不自动加入旧任务。
5. 已有正式标注的图片也可产生候选框；原有正式标注始终保留。
6. 未完成任务可持续查看进度，关闭页面不影响执行，已产出的图片可先审核。
7. 支持取消任务、重试失败图片；修改 Prompt 或转换配置后创建新批次。

Prompt 是识别要求，类别映射是导入契约。例如“标注无人机”对应已存在的“无人机”类别。不存在的类别按现有类别管理权限创建，禁止模型自行生成数据库类别 ID。

### 1.2 图片浏览与审核

- 分页浏览图片，缩略图按需叠加预标注框；显示任务批次和框数量。
- 按是否存在候选框、执行状态、审核状态、任务批次筛选。
- 区分成功空结果、尚未处理、处理中、请求失败与验证失败。
- 进入图片后分别展示正式标注和本批次候选框；支持显示 / 隐藏候选层。
- 支持移动、调整、修改类别、删除、补画与撤销 / 重做。
- 保存草稿不计为审核通过，重新进入或刷新后草稿仍存在。
- “通过并下一张”将最终审核结果合并到正式标注；“驳回”保存审核结论，不导入。
- 删除全部候选框后，可确认无目标，也可驳回本次结果。存在正式标注时，不因空候选结果清除正式标注或标记整图无目标。
- 下一张遵循当前筛选结果，不使用现有随机领取图片队列替代审核导航。
- 同一图片存在多个任务结果时，默认选择一个批次；其他批次显式切换，避免无意叠加重复框。

### 1.3 第一版边界

包含 OpenAI 兼容接口、通用 HTTP JSON 请求模板、矩形与当前四点 Schema、抽样与全量任务、结果叠加、筛选、编辑和审核。

multipart、任意脚本适配、实时流式模型响应、模型部署 / 微调、自动免审核发布、多数据集联合任务不属于第一版。端点配置保留用户自己的局域网或自托管服务使用方式。

## 2. 架构

```text
Vue：配置 / Prompt / 任务进度 / 图片筛选 / 审核画布
                           |
FastAPI：认证授权、任务创建、查询、草稿保存、审核事务
                           |
MySQL：配置、任务、图片执行状态、候选框、正式标注
                           |
独立 worker：领取任务图片 → HTTP 推理 → 转换验证 → 提交结果
```

- 第一版使用 MySQL 8 持久队列，继续使用 PyMySQL 和原生 SQL。
- API 创建任务后返回 `202` 和任务 ID；前端用短轮询获取进度。取消页面请求不取消任务。
- worker 独立于 API 进程，不使用 FastAPI `BackgroundTasks` 或请求内循环承载长任务。
- 在短事务内领取任务图片，随后释放连接，再进行网络推理；结果在另一短事务内写入。
- 更新 `dev.sh` 和运行文档，独立管理 worker 的 PID、日志和启停；停止服务保留任务记录。
- worker 使用有界并发和每端点限流，避免一次全量任务耗尽推理资源。

## 3. 推理接口与 Schema 契约

### 3.1 配置

- endpoint、HTTP 方法、模型名、认证及自定义请求头。
- OpenAI 兼容模式，以及受控的 HTTP JSON 请求模板。
- 图片传输以服务端读取文件并构造 data URL 为默认方式，不把平台 localhost 地址当作远程模型可访问的图片地址。
- 模板占位符：图片、用户 Prompt、类别集合和输出 Schema。
- 响应提取路径、字段映射、坐标约定（原图像素 / 0–1 / 0–1000）。
- 服务端超时、重试上限、响应大小和目标数量限制。
- 可选原生结构化输出；按实际服务版本选择请求参数，不能假定所有兼容接口支持同一扩展。
- 请求配置采用声明式模板，不执行用户提供的 Python、JavaScript 或 shell。
- 配置按用户所有权与共享权限管理；凭据仅后端使用，加密持久化，响应与日志脱敏。

### 3.2 标准输出

最终候选几何与 `AnnotationCreate` / `SaveAnnotationsRequest` 兼容：

```json
{
  "annotations": [
    {
      "category_id": 12,
      "annotation_type": "bbox",
      "x_center": 0.5,
      "y_center": 0.4,
      "width": 0.2,
      "height": 0.1
    }
  ]
}
```

四点结果补充现有 `p1_x` 至 `p4_y` 字段，平台根据顶点计算外接框。任务、来源和审核字段放在候选记录外层，不要求模型生成。

验证管线：

1. HTTP 调用与响应大小检查，拒绝截断、无法解析或不符合模板的响应。
2. 结构验证：形状枚举、必需字段、类型、数量上限。
3. 业务验证：类别属于目标数据集，坐标有限、范围合法，矩形面积为正，四点顺序及几何有效。
4. 明确坐标转换规则；不靠数值范围猜测输出坐标体系。
5. 原始模型响应和转换诊断与候选结果分别保存，失败不会被解释为“无目标”。

首版采用每张图片整体验证：存在非法候选时，该图片标记验证失败并提供原因，不静默丢弃非法框后报告成功。模型自行输出的 confidence 仅供参考，不用于自动审核。

## 4. 数据结构与状态

### 4.1 新增表

| 表 | 主要职责 |
| --- | --- |
| `preannotation_profiles` | 推理配置、所有者、共享权限、凭据及版本 |
| `preannotation_tasks` | 数据集、创建者、Prompt、非敏感配置与类别 / Schema 快照、任务状态和计数 |
| `preannotation_task_images` | 固定图片清单、执行状态、审核状态、尝试次数、租约、错误、原始结果、草稿版本 |
| `preannotations` | 兼容当前几何的候选框、原始几何、编辑几何、补画来源、软删除和导入关联 |

任务中的凭据通过受保护引用使用，不在快照或日志中复制明文。配置更新不改变任务的 Prompt、类别和转换规则；凭据撤销导致明确的授权错误。

增加必要的唯一约束和索引：任务与图片唯一；任务、执行状态及租约；任务、审核状态与图片；候选所属任务图片。使用稳定的候选 ID，避免循环添加时的时间戳 ID 碰撞。

正式标注补充来源关联，图片或标注集合补充修订版本，保证重复审核可识别、人工编辑冲突可检测。所有正式标注写入路径必须遵守同一版本和来源规则，不能只保护新审核接口。

### 4.2 分离状态

- 任务：`queued / running / cancelling / cancelled / completed / completed_with_errors / failed`。
- 图片执行：`queued / running / succeeded / failed / cancelled`；`succeeded` 可以是合法空结果。
- 审核：`unreviewed / draft / approved / rejected`。
- 原有图片标注：继续保留 `pending / assigned / labeled / skipped`，预标注生成不修改该状态。

候选数量区分模型原始数量和当前未删除数量。删除所有框后仍保留“曾产生结果”和编辑记录，筛选不会把它误认为未执行。

## 5. 任务可靠性与审核一致性

### 5.1 执行

- 使用 MySQL 事务及 `FOR UPDATE SKIP LOCKED` 领取任务图片，领取后立即提交。
- 使用租约、心跳和领取版本识别失效 worker；租约到期后可恢复领取。
- 外部推理可能因故障重复调用，采用至少一次执行；数据库结果通过唯一键、领取版本和事务保证不重复写入。
- 有限重试临时网络错误、超时及明确可重试状态；认证失败、配置错误及验证错误提供诊断，不无限重试。
- 取消标志阻止继续领取；在途请求结束后再次检查取消状态与领取版本，迟到响应不能污染结果。
- 重试失败图片只重排该批次失败项，不清除成功或已审核结果。
- 任务计数以图片终态为依据；尝试次数不计为已处理图片。最终状态反映部分失败。
- worker、API 重启后可恢复；任务状态能在所有图片终结后重新汇总，避免永久停留在 running。
- 数据集删除、类别移除、图片文件缺失等情况有明确终态或可诊断错误。

### 5.2 审核

- worker 不更新人工草稿、已审核结果及正式标注。
- 保存草稿和审核使用修订版本，冲突返回 `409`，避免多人最后写入覆盖。
- 通过审核时，在同一事务中验证当前图片 / 类别与修订版本、合并候选、记录来源、更新审核状态和统计。
- 已有正式标注始终保留；对重复候选提供可视比较与人工删除，不隐式替换。
- 重复点击、请求重试或重复通过不重复导入或重复累计工作量。
- 现有 `/images/{id}/save` 删除后重建的行为需要兼容来源与版本；审核接口不能直接无条件调用旧保存逻辑。
- 空结果经人工确认后可标记无目标；若已有正式框则保留正式框并保持对应标注状态。
- 人工审核完成前，默认导出只包含现有正式标注，候选结果不进入训练数据。

## 6. 建议 API

所有接口沿用 `/api` 与当前 JWT 认证，用户只能操作有权访问的数据集、配置和任务。普通用户的任务入口按现有数据集访问规则开放；共享配置和全局管理遵循管理员权限。

| 方法与路径 | 功能 |
| --- | --- |
| `GET/POST /api/preannotation/profiles` | 列出 / 创建接口配置 |
| `GET/PUT/DELETE /api/preannotation/profiles/{id}` | 管理本人或有权管理的配置 |
| `POST /api/datasets/{id}/preannotation-tasks` | 创建抽样或全量后台任务 |
| `GET /api/datasets/{id}/preannotation-tasks` | 分页查看任务批次 |
| `GET /api/preannotation/tasks/{id}` | 进度、终态与错误摘要 |
| `POST /api/preannotation/tasks/{id}/cancel` | 取消任务 |
| `POST /api/preannotation/tasks/{id}/retry-failed` | 重试失败图片 |
| `GET /api/datasets/{id}/images` | 分页、候选数量 / 执行 / 审核状态筛选 |
| `GET /api/preannotation/tasks/{id}/images/{image_id}` | 正式框、候选框、草稿及修订版本 |
| `PUT /api/preannotation/tasks/{id}/images/{image_id}/draft` | 保存编辑、删除与补画 |
| `POST /api/preannotation/tasks/{id}/images/{image_id}/review` | 通过 / 驳回 / 确认无目标 |

响应和筛选必须包含明确 task_id；不以隐式“最新任务”替代批次选择。访问 endpoint 的权限、HTTP(S) 协议与资源限制在服务端执行，同时允许用户授权使用自托管和局域网服务。
